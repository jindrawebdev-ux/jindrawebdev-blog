HTACCESS CHANGES FOR YOUR ROOT .htaccess
=========================================

Three additions. Rule 1 is required for blog article URLs and is already
applied. Rules 2 and 3 are security and speed improvements.

Nothing else in your existing .htaccess needs to change.


-------------------------------------------------------------------
1. BLOG ARTICLE URLS  (required — already applied)
-------------------------------------------------------------------

/blog works automatically once blog.php exists at your site root (the
same way /about -> about.php). Individual articles need one rule,
because there's no physical .php file per article — they're all served
dynamically through article.php.

Add BEFORE the block labeled "# Serve .php files when clean URLs are
requested" (that's the generic catch-all — this rule has to run first
so it doesn't fall through to a 404):

    # Blog article pages: /blog/{slug} -> /article.php?slug={slug}
    RewriteRule ^blog/([a-z0-9\-]+)/?$ /article.php?slug=$1 [L,QSA]


-------------------------------------------------------------------
2. PROTECT SENSITIVE FILES  (recommended)
-------------------------------------------------------------------

Your error_log sits in the web root, which means it is very likely
readable by anyone at https://jindrawebdev.com/error_log — that leaks
your server paths and internal error details. This blocks it, along
with the PHP config file and any backup copies.

Add at the very END of your .htaccess:

    # ---- Block access to sensitive files ----
    <FilesMatch "^(error_log|php_errors\.log|\.user\.ini|\.htaccess|\.htpasswd)$">
        <IfModule mod_authz_core.c>
            Require all denied
        </IfModule>
        <IfModule !mod_authz_core.c>
            Order allow,deny
            Deny from all
        </IfModule>
    </FilesMatch>

    # ---- Block backup/source files left in the web root ----
    <FilesMatch "\.(bak|backup|old|orig|save|swp|sql|log|ini)$">
        <IfModule mod_authz_core.c>
            Require all denied
        </IfModule>
        <IfModule !mod_authz_core.c>
            Order allow,deny
            Deny from all
        </IfModule>
    </FilesMatch>

IMPORTANT: this also blocks about.php.backup, which is what you want.
A .backup copy of a PHP file is served as PLAIN TEXT instead of being
executed, so without this anyone could read your source code through it.

The blog's data folder is handled separately by blog-data/.htaccess,
which deploys automatically with the rest of the blog files.


-------------------------------------------------------------------
3. COMPRESSION AND CACHING  (recommended — speeds up every page)
-------------------------------------------------------------------

Add at the very END of your .htaccess, after the block above:

    # ---- Gzip compression ----
    <IfModule mod_deflate.c>
        AddOutputFilterByType DEFLATE text/html text/plain text/xml text/css
        AddOutputFilterByType DEFLATE application/javascript application/x-javascript
        AddOutputFilterByType DEFLATE application/json application/xml
        AddOutputFilterByType DEFLATE image/svg+xml
    </IfModule>

    # ---- Browser caching ----
    <IfModule mod_expires.c>
        ExpiresActive On
        ExpiresByType image/jpeg              "access plus 1 year"
        ExpiresByType image/png               "access plus 1 year"
        ExpiresByType image/webp              "access plus 1 year"
        ExpiresByType image/svg+xml           "access plus 1 year"
        ExpiresByType image/x-icon            "access plus 1 year"
        ExpiresByType video/mp4               "access plus 1 year"
        ExpiresByType text/css                "access plus 1 month"
        ExpiresByType application/javascript  "access plus 1 month"
        ExpiresByType font/woff2              "access plus 1 year"
        ExpiresByType text/html               "access plus 0 seconds"
    </IfModule>

Images and CSS get cached in visitors' browsers, so repeat visits load
almost instantly. HTML is deliberately never cached, so content edits
show up immediately.

If your host doesn't have mod_deflate or mod_expires enabled, the
IfModule guards make these blocks do nothing rather than error — safe
to add either way.
